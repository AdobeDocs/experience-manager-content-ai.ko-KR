# AEM 컨텐츠 AI 검색 시작

기존 사이트 검색은 방문자가 콘텐츠에 있는 단어와 비교하여 입력한 단어를 일치시킵니다. 이는 방문자가 콘텐츠와 동일한 용어를 사용할 때 잘 작동하지만, 질문을 하거나 의도를 표현하거나 단순히 내용을 다르게 표현하는 순간 중단됩니다. 검색은 사이트 방문자의 의도를 나타내는 가장 명확한 신호 중 하나이므로 실패한 일치는 종종 여정 실패를 의미합니다. 콘텐츠가 검색되지 않고, 참여가 중단되고, 전환이 손실됩니다. 방문자들은 검색이 단순히 입력한 내용이 아니라 의미를 이해하기를 점점 더 기대합니다. 또한 처음부터 생성 가능한 답변을 가능하게 하는 것은 동일한 의도 인식 기반입니다.

AEM 컨텐츠 AI 검색은 사이트의 검색 경험을 대체하지 않습니다. 키워드 일치에서 의미와 의도 이해, 질문에 직접 답변하기 등 사이트 검색 경험이 진화합니다. 의미 체계 검색은 기존 검색 경험 위에 의도 인식 검색을 추가하여 쿼리가 콘텐츠의 정확한 단어를 공유하지 않는 경우에도 관련 콘텐츠를 표시합니다. 생성 검색은 이와 동일한 검색 기반을 기반으로 사이트의 자체 콘텐츠에 기반을 둔 상황별 생성 답변을 생성합니다. 의미 검색과 동일한 단계가 아닌 고유한 단계입니다.

방문자의 경우 관련성 향상, 자연어 지원, 결과 없는 검색 감소, 답변 속도를 의미합니다. 비즈니스를 위해 검색 경험을 처음부터 다시 빌드하지 않고도 더 나은 의도 일치, 더 강력한 콘텐츠 검색 및 AI 기반 검색 기반을 의미합니다. 또한 기존 검색 구성 요소를 완전히 새로운 구현이 필요 없이 단계별로 어휘에서 의미 체계로, 생성 기능으로 이동할 수 있으므로 팀의 경우 점진적 업그레이드입니다.

여기에서 두 가지 결정, 즉 콘텐츠가 콘텐츠 AI에 삽입되는 방식과 방문자에게 제공하는 구성 요소가 나옵니다. 콘텐츠를 연결한 다음 검색 구성 요소를 페이지에 추가하면 사이트에서 방문자에게 가장 관련성 있는 결과와 의도 기반의 답변을 제공할 수 있습니다.

## 사전 요구 사항 {#prerequisites}

시작하기 전에 다음 조건이 충족되는지 확인하십시오.

* 하나 이상의 AEM as a Cloud Service 환경이 있는 활성 Cloud Manager 프로그램을 갖고 있습니다.
* 사용자가 **게시** 계층에서 할당된 **[!UICONTROL AEM 사용자]** 제품 프로필(콘텐츠 소스를 보기 위해) 및/또는 **[!UICONTROL AEM 관리자]**(만들고 편집하기 위해)에 할당됩니다. 콘텐츠 AI 색인은 작성된 콘텐츠가 아닙니다. 전체 절차는 [AEM 제품 프로필에 사용자 할당](contentsources.md#assign-product-profile)을 참조하십시오.
* 환경의 제품 프로필이 **Adobe Admin Console**&#x200B;에서 프로비저닝되었습니다.

>[!NOTE]
>
>Cloud Manager에 대한 액세스 만으로는 충분하지 않습니다. 또한 사용자는 콘텐츠 소스를 보거나 관리하기 위해 게시 계층에서 할당된 AEM 제품 프로필이 필요합니다.

## 1a단계 - 기존 색인 연결 {#option-a}

기존 저장소 인덱스는 페이지, Assets 또는 컨텐츠 조각과 같이 인덱싱된 항목으로 표시되는 Source 유형 AEM으로 컨텐츠 소스 목록에 자동으로 표시됩니다. **제한됨**&#x200B;에서 시작하며 잠겨 있지만 콘텐츠 AI를 통해 아직 검색할 수 없습니다.

1. [Cloud Manager](https://my.cloudmanager.adobe.com/)에 로그인하고 프로그램을 선택한 다음 구성할 환경의 **[!UICONTROL 콘텐츠 AI 구성]** 탭을 엽니다.
1. 검색할 원본(예: **페이지**)을 찾은 다음 잠금 아이콘을 선택합니다. **[!UICONTROL AEM 관리자]** 제품 프로필이 있는 사용자만 이 작업을 수행할 수 있습니다. **[!UICONTROL AEM 사용자]**&#x200B;는 콘텐츠 소스를 볼 수 있으며 검색 기능은 변경할 수 없습니다.
1. **소스를 검색할 수 있도록 설정**&#x200B;을(를) 읽으십시오. 신중하게 대화합니다. 또한 검색이 가능하면 Apache Oak 액세스 제어 목록(ACL)이 이 인덱스에 대해 적용되지 않는다고 경고합니다. 인증된 사용자는 모든 콘텐츠를 검색할 수 있습니다. **ACL(액세스 제어)이 적용되지 않으며 이 원본의 모든 콘텐츠를 검색할 수 있음을 이해합니다**&#x200B;를 확인한 다음 **검색 가능하게 만들기**&#x200B;를 선택하십시오.
1. **사용 가능** 상태 변경 내용을 확인합니다. 경고 아이콘은 소스 옆에 계속 표시되므로 ACL이 사용되지 않습니다.
1. 테스트 검색을 실행하여 결과가 올바르게 돌아오는지 확인합니다.

>[!WARNING]
>
>이러한 방식으로 기존 인덱스를 검색할 수 있게 만들면 해당 소스에 대한 Apache Oak ACL을 완전히 우회합니다. 인증된 사용자는 일반 저장소 권한에 관계없이 검색을 통해 모든 콘텐츠를 검색할 수 있습니다. 노출하기 쉬운 소스에만 이 작업을 수행합니다.

>[!NOTE]
>
>이 경로는 사이트의 콘텐츠(예: 페이지 콘텐츠)가 있는 색인이 이미 있는 경우 적합합니다. 개별 인덱스 메커니즘을 설정하는 대신 해당 인덱스를 사용하십시오.

## 단계 1b - 크롤링 웹 사이트 {#option-b}

사이트에 대한 검색 색인이 아직 없는 경우 이 경로를 사용합니다. 콘텐츠 AI의 자체 웹 크롤러는 하나를 빌드하고 새로 고칩니다. 이 프로세스를 **획득{1 Cloud Manager 및 이 안내서라고도 합니다.**

1. 1a단계와 동일하게 **[!UICONTROL 콘텐츠 AI 구성]** 탭을 엽니다.
1. **[!UICONTROL Source 만들기]**&#x200B;를 선택하고 필드를 채웁니다. **[!UICONTROL AEM 관리자]** 제품 프로필이 있는 사용자만 새 콘텐츠 소스를 추가할 수 있습니다.

   | 필드 | 설명 |
   | --- | --- |
   | **[!UICONTROL 콘텐츠 AI 구성 이름]** | 해당 소스에 대한 고유 식별자. 생성 후에는 변경할 수 없습니다. |
   | **[!UICONTROL 웹 사이트 주소]** | 루트 URL을 크롤링으로 변환(예: `https://www.example.com/`) |
   | **[!UICONTROL URL 제외]** | *(선택 사항)* 크롤하는 동안 건너뛸 URL 패턴입니다. |
   | **[!UICONTROL 새로 고침 빈도]** | 매주, 매일, 매일 4×, 60분 또는 15분. |

1. **[!UICONTROL 소스 만들기]**&#x200B;를 선택합니다. 확보가 자동으로 시작되고 소스가 **색인화**&#x200B;로 이동합니다.
1. **사용 가능**&#x200B;에 도달할 때까지 상태 모니터링:

   | 상태 | 의미 |
   | --- | --- |
   | **신규** | Source이 방금 생성되었습니다. 자동 획득이 아직 시작되지 않았습니다. |
   | **색인화** | 진행 중인 색인 생성 |
   | **사용 가능** | 색인화 완료 - 검색 쿼리를 제공할 준비가 되었습니다. |

1. 소스 옆에 있는 **검색** 아이콘을 선택하고 테스트 쿼리를 실행하여 콘텐츠가 올바르게 인덱싱되었는지 확인하십시오.

>[!CAUTION]
>
>소스가 **[!UICONTROL 인덱싱]**&#x200B;에서 중단되었습니까? 먼저 (...) 메뉴에서 획득을 다시 시도하십시오. 그래도 진행되지 않으면 웹 사이트 주소를 공개적으로 연결할 수 있고 **[!UICONTROL URL 제외]** 패턴이 모든 페이지를 필터링하지 않는지 확인하십시오.

## 2단계 - 검색 구성 요소 선택 {#choose-component}

페이지에 검색을 지정할 수 있는 두 가지 구성 요소가 서로 다른 기본 기반으로 구축됩니다.

| | 의미 체계 검색을 사용한 빠른 검색(v3) | AEM 컨텐츠 AI 검색 |
| --- | --- | --- |
| 기초 | v3로 업그레이드된 기존 빠른 검색 핵심 구성 요소 | 새로운 독립형 구성 요소 - 콘텐츠 AI API를 직접 호출합니다. |
| 콘텐츠 소스 | 이미 인덱스에 있고 의미 체계 일치를 위해 보강된 기존 사이트 콘텐츠 | A Content AI Source (1a 또는 1b단계) |
| 생성적 대답 | 아니요 - 기존 결과 목록의 일치 품질만 개선합니다. | 예 - 소스 및 면책조항이 포함된 선택적 AI 생성 요약 |
| 최적 | 사이트에서 이미 빠른 검색을 사용하고 있으며 더 가벼운 증분 업그레이드를 원하는 경우 | 시맨틱 검색, 생성 검색 및 NLS(자연어 검색)와 같은 콘텐츠 AI 기능의 전체 범위에 대해 제안된 구성 요소입니다 |

## 의미 체계 검색을 사용한 빠른 검색(v3) {#quicksearch}

사이트에서 이미 클래식 [!DNL AEM] 빠른 검색 구성 요소를 사용하는 경우 v3에서 옵트인 **AI 검색**&#x200B;을(를) 추가하여 방문자가 전환할 수 있습니다. 새 구성 요소, 프록시 또는 컨텐츠 Source은 필요하지 않습니다.

* 검색은 오늘과 동일한 JCR/QueryBuilder 경로를 통해 계속 실행되며, 결과 서블릿이나 결과가 렌더링되는 방법은 변경되지 않습니다.
* 방문자가 토글을 활성화하면 구성 요소가 쿼리에 일반 키워드 전체 텍스트 대신 의미 체계 일치로 라우팅하는 특수 마커를 접두사로 추가합니다.
* 이 경로에 생성적 대답 요약이 없습니다. 기존 결과 목록의 일치 품질을 향상시키며, 생성 AI 답변을 추가하지 않습니다.
* **1단계(콘텐츠 AI 온보딩)가 이 경로에 적용되지 않습니다.** 만들거나 연결할 컨텐츠 Source이 없습니다. 이 구성 요소는 기존 페이지 인덱스를 직접 쿼리합니다.

>[!NOTE]
>
>토글을 활성화한 후 의미 체계 검색이 예상대로 작동하지 않으면 지원 티켓을 높입니다.

이 경로는 새 구성 요소나 콘텐츠 소스를 채택하지 않고 증분 시맨틱 검색 업그레이드를 원하는 경우 적합합니다. 생성적 대답 경험을 원하는 경우 올바른 경로가 아닙니다. AEM 컨텐츠 AI 검색을 사용하십시오.

## AEM 컨텐츠 AI 검색 {#gensearch}

AEM 컨텐츠 AI 검색은 방문자가 시맨틱 검색 및 생성 검색 기능을 모두 사용하여 페이지에서 바로 컨텐츠 Source을 검색할 수 있도록 하는 [!DNL AEM] 핵심 구성 요소입니다.

>[!VIDEO](https://video.tv.adobe.com/v/3497308)

>[!NOTE]
>
>생성 검색 기능은 AI SKU를 통해 별도로 구매합니다. 계정에 대해 활성화하려면 Adobe 영업 담당자에게 문의하십시오.

### 사전 요구 사항 {#gensearch-prerequisites}

* 프로젝트에 [!DNL AEM] 핵심 구성 요소가 설치되어 있습니다.
* 하나 이상의 콘텐츠 Source이 이미 만들어졌고 **사용 가능** 상태입니다.
* **AEM Content AI Client** OSGi 구성(`ContentAIClientImpl`)이 작성자와 게시 모두에 설정되었으며, 올바른 API 자격 증명과 기본 Content Source이 있습니다.

작성자가 구성 요소를 사용할 수 있도록 설정하고, 클라이언트 라이브러리를 연결하고, 대화 상자를 구성하는 데 필요한 전체 설치 가이드는 [핵심 구성 요소 설명서](https://www.adobe.com/go/aem_cmp_library)를 참조하십시오.
