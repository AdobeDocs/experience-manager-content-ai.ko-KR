# AEM 콘텐츠 AI 검색 시작하기

기존 사이트 검색은 방문자가 입력한 단어와 콘텐츠에 있는 단어를 비교하여 일치하는 부분을 찾습니다. 방문자가 콘텐츠와 동일한 용어를 사용할 때 잘 작동합니다. 질문을 하거나 의도를 표현하거나 사물을 다르게 표현하면 실패한다. 검색은 사이트 방문자의 의도를 나타내는 가장 명확한 신호 중 하나이므로 매칭 실패는 여정 실패를 의미하는 경우가 많습니다. 콘텐츠가 검색되지 않고, 참여가 중단되고, 변환은 손실됩니다. 방문자들은 검색이 단순히 입력한 내용이 아니라 의미를 이해하기를 점점 더 기대하고 있습니다. 동일한 의도 인식 토대 역시 생성적 답변을 가능하게 한다.

AEM 콘텐츠 AI 검색은 사이트의 검색 환경을 대신하는 것이 아닙니다. 키워드 매칭부터 의미와 의도 이해, 질문에 직접 답변하기 등과 같이 사이트 검색 환경을 진화시킵니다. 시맨틱 검색은 기존 검색 환경에 의도 인식 검색 기능을 추가하여, 쿼리가 콘텐츠의 단어를 정확히 담고 있지 않은 경우에도 관련 콘텐츠를 표시합니다. 생성형 검색은 이와 동일한 검색 체계를 통해 사용자 사이트의 자체 콘텐츠에 기반을 둔 상황별 답변을 생성합니다. 이는 시맨틱 검색과 동일한 단계 아닌 고유한 단계입니다.

방문자에게 있어 이는 관련성 향상, 자연어 지원, 결과 없는 검색 감소, 더 빠른 답변 속도를 의미합니다. 기업에게 있어 이는 검색 환경을 처음부터 다시 빌드하지 않고도 더 나은 의도 매칭, 더 강력한 콘텐츠 검색, AI 기반의 검색 체계를 의미합니다. 또한 기존 검색 구성 요소가 새로운 구현을 요구하지 않고, 차근차근 의미 체계에서 단계별로 생성 기능으로 이동할 수 있으므로 팀의 경우 점진적 업그레이드입니다.

이를 위해 콘텐츠를 콘텐츠 AI에 포함시키는 방법과 방문자에게 제공하는 구성 요소, 이렇게 두 가지 결정을 내립니다. 방문자에게 관련 결과와 의도 기반 답변을 제공하려면 콘텐츠를 연결한 다음 검색 구성 요소를 페이지에 추가합니다.

## 사전 요구 사항 {#prerequisites}

시작하기 전에 다음 조건이 충족되는지 확인하십시오.

* 하나 이상의 AEM as a Cloud Service 환경이 있는 활성 Cloud Manager 프로그램을 갖고 있습니다.
* 사용자는 **작성자** 및 **게시** 계층 모두에서 **[!UICONTROL AEM 사용자]** 제품 프로필(콘텐츠 소스를 보기 위해) 및/또는 **[!UICONTROL AEM 관리자]**(만들고 편집하기 위해)에 할당됩니다. 전체 절차를 보려면 [AEM 제품 프로필에 사용자 할당](contentsources.md#assign-product-profile)을 참조하십시오.
* **Adobe Admin Console**&#x200B;에서 환경 제품 프로필이 프로비저닝되었습니다.

>[!NOTE]
>
>Cloud Manager에 대한 액세스만으로는 충분하지 않습니다. 또한 사용자는 콘텐츠 소스를 보거나 관리하기 위해 작성자 및 게시 계층 모두에 할당된 AEM 제품 프로필이 필요합니다.

## 1a 단계 - 기존 색인 연결 {#option-a}

기존의 저장소 인덱스는 콘텐츠 소스 목록에 소스 타입 AEM으로 자동으로 나타나 페이지, 에셋, 콘텐츠 조각같이 색인화된 항목으로 표시됩니다. **제한됨** 및 잠김으로 시작되며, 아직은 콘텐츠 AI를 통해 검색할 수 없습니다.

1. [Cloud Manager](https://my.cloudmanager.adobe.com/)에 로그인하고 프로그램을 선택한 다음 구성할 환경의 **[!UICONTROL 콘텐츠 AI 구성]** 탭을 엽니다.
1. 검색할 소스(예: **페이지**)를 찾은 다음 잠금 아이콘을 선택합니다. **[!UICONTROL AEM 관리자]** 제품 프로필이 있는 사용자만 이 작업을 수행할 수 있습니다. **[!UICONTROL AEM 사용자]**&#x200B;는 콘텐츠 소스를 볼 수 있지만 검색 권한은 변경할 수 없습니다.
1. **소스를 검색 가능하도록 만드시겠습니까?**&#x200B;를 읽어 보십시오. 신중하게 대화하십시오. 이 색인은 검색이 가능해진 후 Apache Oak 액세스 제어 목록(ACL)이 이 색인에 대해 적용되지 않음을 경고합니다. 인증된 사용자는 모든 컨텐츠를 검색할 수 있습니다. **액세스 제어(ACL)가 적용되지 않으며 이 소스의 모든 콘텐츠를 검색할 수 있음을 이해합니다**&#x200B;를 선택한 다음 **검색 가능하도록 만들기**&#x200B;를 선택합니다.
1. 상태가 **사용 가능**&#x200B;으로 변경되는지 확인합니다. ACL이 사용되지 않는다는 영구적 알림으로 경고 아이콘이 소스 옆에 계속 표시됩니다.
1. 결과를 확인하려면 테스트 검색을 실행하십시오.

>[!WARNING]
>
>이와 같이 기존 인덱스를 검색 가능하도록 만들면 해당 소스에 대해 Apache Oak ACL을 완전히 우회하게 됩니다. 인증된 사용자는 정상적인 저장소 권한에 관계없이 모든 콘텐츠를 검색할 수 있습니다. 전체를 노출해도 무방한 소스에만 이 작업을 수행하십시오.

>[!NOTE]
>
>페이지 콘텐츠와 같은 사이트 콘텐츠가 포함된 색인이 이미 있는 경우 이 경로를 사용하십시오. 별도의 크롤링 메커니즘을 설정하는 대신 그러한 인덱스를 사용하십시오.

## 1b 단계 - 웹 사이트 크롤링 {#option-b}

사이트에 대한 검색 인덱스가 아직 없는 경우 이 경로를 사용하십시오. 콘텐츠 AI의 자체 웹 크롤러가 검색 인덱스를 빌드하고 새로 고칩니다. Cloud Manage와 이 안내서 전체에서 이 크롤링 프로세스를 **확보**&#x200B;라고도 표현합니다.

1. 1a 단계와 마찬가지로 **[!UICONTROL 콘텐츠 AI 구성]** 탭을 엽니다.
1. **[!UICONTROL 소스 만들기]**&#x200B;를 선택하고 필드를 채웁니다. **[!UICONTROL AEM 관리자]** 제품 프로필이 있는 사용자만 새 콘텐츠 소스를 추가할 수 있습니다.

   | 필드 | 설명 |
   | --- | --- |
   | **[!UICONTROL 콘텐츠 AI 구성 이름]** | 이 소스의 고유 식별자입니다. 생성 후에는 변경할 수 없습니다. |
   | **[!UICONTROL 웹 사이트 주소]** | 크롤링할 루트 URL(예: `https://www.example.com/`)입니다. |
   | **[!UICONTROL URL 제외]** | *(선택 사항)* 크롤하는 동안 건너뛸 URL 패턴입니다. |
   | **[!UICONTROL 새로 고침 빈도]** | 매주, 매일, 매일 4회, 60분 또는 15분 |

1. **[!UICONTROL 소스 만들기]**&#x200B;를 선택합니다. 확보가 자동으로 시작되고 소스가 **색인화**&#x200B;로 이동합니다.
1. 상태가 **사용 가능**&#x200B;이 될 때까지 모니터링:

   | 상태 | 의미 |
   | --- | --- |
   | **신규** | 소스가 방금 생성되었으며, 자동 확보는 아직 시작되지 않았습니다. |
   | **색인화** | 크롤링 및 색인화 진행 중입니다. |
   | **사용 가능** | 색인화 완료 - 검색 쿼리를 제공할 준비가 되었습니다. |

1. 콘텐츠가 올바르게 인덱싱되었는지 확인하려면 원본 옆에 있는 **검색** 아이콘을 선택하고 테스트 쿼리를 실행하십시오.

>[!CAUTION]
>
>소스가 **[!UICONTROL 인덱싱]**&#x200B;에 남아 있으면 먼저 (...) 메뉴에서 획득을 다시 시도하십시오. 그래도 진행되지 않으면 웹 사이트 주소를 공개적으로 연결할 수 있고 **[!UICONTROL URL 제외]** 패턴이 모든 페이지를 필터링하지 않는지 확인하십시오.

## 2단계 - 검색 구성 요소 선택 {#choose-component}

서로 다른 토대 위에서 페이지에 검색을 지정할 수 있는 두 가지 구성 요소가 있습니다.

| | 시맨틱 검색을 사용한 빠른 검색(v3) | ATM 콘텐츠 AI 검색 |
| --- | --- | --- |
| 기초 | v3로 업그레이드된 기존의 빠른 검색 핵심 구성 요소 | 새로운 독립형 구성 요소 - 콘텐츠 AI API를 직접 호출합니다. |
| 콘텐츠 소스 | 이미 인덱스에 있고 시맨틱 매칭을 위해 보강된 기존의 사이트 콘텐츠 | 콘텐츠 AI 소스(1a 또는 1b 단계) |
| 생성형 답변 | 아니요 - 기존 결과 목록의 매칭 품질만 개선합니다. | 예 - 소스 및 면책조항이 포함된 선택적 AI 생성 요약 |
| 최적 | 이미 빠른 검색을 사용하고 있으며 더 가벼운 증분 업그레이드를 원하는 사이트 | 시맨틱 검색, 생성형 검색, 자연어 검색(NLS)과 같은 콘텐츠 AI 기능 전체를 대상으로 제안된 구성 요소 |

## 시맨틱 검색을 사용한 빠른 검색(v3) {#quicksearch}

사이트에서 이미 클래식 [!DNL AEM] 빠른 검색 구성 요소를 사용하는 경우, v3에서는 방문자가 켤 수 있는 옵트인 **AI 검색** 토글을 추가합니다. 새 구성 요소, 프록시 또는 콘텐츠 소스는 필요하지 않습니다.

* 검색은 여전히 지금과 동일한 JCR/QueryBuilder 경로를 통해 계속 실행되며, 결과 서블릿 또는 결과가 렌더링되는 방법은 달라지지 않습니다.
* 방문자가 토글을 활성화하면 구성 요소가 쿼리에 일반 키워드 전체 텍스트 검색 대신 의미 체계 일치로 라우팅하는 특수 마커를 접두사로 추가합니다.
* 이 경로에는 생성 답변 요약이 없습니다. 이는 기존 결과 목록의 일치 품질을 향상시키며, 생성형 AI 답변은 추가되지 않습니다.
* **1단계(콘텐츠 AI 온보딩)는 이 경로에 적용되지 않습니다.** 만들거나 연결할 콘텐츠 소스가 없습니다. 이 구성 요소는 기존의 페이지 인덱스를 직접 쿼리합니다.

>[!NOTE]
>
>토글을 활성화한 후 시맨틱 검색이 예상대로 작동하지 않으면 지원 티켓을 높이십시오.

새 구성 요소나 콘텐츠 소스를 채택하지 않고 증분 의미 체계 검색을 업그레이드하려면 이 경로를 사용하십시오. 생성적 답변 경험을 원하는 경우 올바른 경로가 아닙니다. AEM 컨텐츠 AI 검색을 사용하십시오.

## ATM 콘텐츠 AI 검색 {#gensearch}

AEM 콘텐츠 AI 검색은 방문자가 시맨틱 검색 및 생성형 검색 기능을 모두 사용하여 페이지에서 바로 콘텐츠 소스를 검색할 수 있도록 하는 [!DNL AEM] 핵심 구성 요소입니다.

>[!VIDEO](https://video.tv.adobe.com/v/3497308)

>[!NOTE]
>
>생성형 검색 기능은 AI SKU를 통해 별도로 구매합니다. 이 기능을 계정에 대해 활성화하려면 Adobe 영업 담당자에게 문의하십시오.

### 사전 요구 사항 {#gensearch-prerequisites}

* 프로젝트에 [!DNL AEM] 핵심 구성 요소가 설치되어 있습니다.
* 하나 이상의 콘텐츠 소스가 이미 만들어졌고 **사용 가능** 상태입니다.
* 올바른 API 자격 증명과 기본 콘텐츠 소스가 포함된 **AEM 콘텐츠 AI 클라이언트** OSGi 구성(`ContentAIClientImpl`)이 작성자와 게시 모두에 설정되었습니다.

작성자가 구성 요소를 사용할 수 있도록 설정하고, 클라이언트 라이브러리를 연결하고, 대화 상자를 구성하는 데 대한 전체 설정 가이드가 필요하면 [핵심 구성 요소 설명서](https://www.adobe.com/go/aem_cmp_library_kr)를 참조하십시오.
